## 1. 提醒（复用 WP3 底座）

新增只读操作 `reminder.plan`，内部用现成的 `createScheduleAdapter`，
没有另写一套调度逻辑。

| 项目 | 结果 |
| --- | --- |
| 服务层 | `reminder.plan` 返回 `{plans, skipped, leadMinutes, windowDays, nowMs}` |
| 界面 | 顶部提醒条，显示未来 7 天到点提醒（时刻 + 标题），最多 3 条，超出折叠计数 |
| 投递 | 仍由宿主 `ctx.schedule` 负责，**界面只显示不投递** |
| 审批 | `reminder.plan` 不进 `WRITE_OPS` / `DANGEROUS_OPS`，`deny` 模式下仍可用 |

### 真机验证（隔离 DSH，端口 62410）

提醒条实际渲染内容：

```
⏰ 提醒  23:15 今晚要提醒我开会   11-09 09:45 周会   11-12 15:45 版本发布
```

提前量 15 分钟计算正确（周会 10:00 → 09:45；版本发布 16:00 → 15:45）。

### 修掉一个真实假警报

界面新建待办时 `dueAt` 是空串。原实现只排除 `undefined`/`null`，
空串经 `Date.parse` 得 `NaN` 后上报 `invalid-dueAt`，于是用户新建一条**正常**待办
就被告知「1 条算不出提醒时刻（数据有问题，不会响）」。

区分已修正：

- 空串 / 空白串 / `null` / `undefined` = **没填** → 不提醒，也不报警
- 非空但解析失败 = **填错** → 进 `skipped`，界面显式显示

变异 W27 验证：去掉空白判断，回归测试立刻变红。

## 3. 两个我自己的操作事故（已修 + 已加防护）

1. 多传一个参数把 `scripts/r3-mutations.json` 当成日志输出路径，
   61 项变异定义被日志文本整体覆盖，紧接着 `git add -A` 把它提交进历史。
   已从上一提交恢复。
2. 第一版防护用 `OUT === MUTATIONS` 比较，而 `argv[2]` 是相对路径、
   `MUTATIONS` 是绝对路径，永不相等 → 防护形同虚设，第二次覆盖差点发生。
   已改成 `resolve()` 归一化后比较，实测 `exit 2` 拦住。
